# Plan: P1b Models track (trained local models)

> Phase P1b of `refdocs/synapse-v4-PRD.md` section 6, decision D-20. Execution doc: `refdocs/execution/2026-10-16-p1b-models-track.md`.

## Why this exists

The owner asked for a trained-model component, "a few different kinds if needed". The PRD's Route stage already says a local classifier answers first and an LLM answers below a confidence threshold, and the enhancement plan lists a distilled router as IDEA-0003, but v4 had no module, data, evaluation or retraining plan for it. In v3 the router was a Keras student (88.1 percent domain, 70.4 percent artifact type) that ran only in shadow mode because nobody could say whether it was good enough. This phase builds the model and, more importantly, the measurement that says when it may be trusted.

## Scope

**In:**
1. A dataset module that loads, audits and splits the v3 data: label counts, stale topic tags, duplicates and train/test leakage.
2. Two baselines: majority class, and a keyword rule built from the taxonomy's labels and hints.
3. A multi-head router (topic with an explicit "outside the syllabus" class, domain, pattern, complexity): TF-IDF features and logistic regression, trained with fixed seeds.
4. A JSON artifact format (vocabulary, idf, weights, labels, feature settings, a content hash) and a pure-Python inference module with no heavy dependency, proved identical to the training library's predictions.
5. A confidence gate chosen on validation data, with coverage and accuracy reported on the held-out test.
6. A model card in `refdocs/evidence/`: data provenance, metrics against baselines, the teacher-noise limit, known failure modes, how to retrain.
7. A router that uses the model above the gate and the LLM seam below it (fake in development).
8. A misconception matcher built as retrieval over the ported list.

**Out (and why):**
- A dense embedding or neural model: A-9 and D-12 say only if measured to help, and the download may not work here. Local follow-up.
- A lane or Kit-fit predictor: no training data until P3 produces generation logs.
- A trained misconception classifier: five examples cannot train anything. The matcher is retrieval and says so.
- A live LLM router: P3, paid (D-08).

## Approach

Measure before trusting. A model joins the pipeline only if it beats both baselines on data it never saw, and only the part of its output above a confidence threshold is used. Everything below the threshold goes to the LLM. The threshold is a validation-set choice, reported with the coverage it buys, so "good enough" is a number, not a feeling.

Labels are an LLM teacher's, with a known self-disagreement rate on styled queries (the v3 notes put it at about 75 percent for one style), so the test measures agreement with the teacher. The model card says this plainly and does not claim the model is right about the world.

## Risks & unknowns

| Risk / unknown | Confidence | Mitigation |
|---|---|---|
| Label noise caps accuracy, especially pattern and complexity | High | Report per head; the gate is per head; low-value heads can be unused |
| 53-way topic accuracy is low with about 40 rows per topic | High that it is | The "none" class and a high gate; fall back to the keyword rule or the LLM |
| Stale topic tags in the older files | Certain (v3 notes) | Use only current-taxonomy tags; report the dropped count |
| Train/test leakage through near-duplicate questions | Medium | Duplicate and near-duplicate audit before any number is reported |
| Pure-Python inference differs from the training library | Low | Parity test on the whole test set, exact predictions |
| The model card flatters the model | Medium | Baselines in the same table; confidence intervals; failure examples listed |

## Definition of done

- The dataset audit is written (counts, dropped rows, duplicates, leakage).
- Held-out accuracy, macro-F1 and, for the gated heads, coverage at the chosen accuracy are reported for the model and both baselines, with intervals.
- The router beats both baselines on at least the domain and topic heads, or the model card says it does not and the router does not use it.
- Retraining twice gives byte-identical artifacts; the pure-Python inference matches the library on every test row.
- `route()` returns the model's answer above the threshold and the LLM fallback's below it, tested without network.
- The misconception matcher has a provenance comment, tests, and a statement that its accuracy is unmeasured.
